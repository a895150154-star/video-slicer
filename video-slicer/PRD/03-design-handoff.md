## 3.1 产品调性关键词

- **专业、效率、不喧哗**
- **知识沉淀的可信感**
- **工具型而非氛围型**
- **PC 桌面端的"快速完成任务"**
- **不要"AI 神秘感"**（市面 AI 工具的紫粉渐变 / 流体动效已经审美疲劳）

> 来源：PRD/01 目标用户「知识类直播博主直播后 1 小时内打开 PC 处理录像」+ 反竞品认知（不模仿录咖的国内娱乐风也不照搬 OpusClip 的科技 SaaS 风）

## 3.2 目标用户视觉感受

- **打开瞬间感受到的应该是**：「这是个能让我快速搞定切片的工具，不会浪费我时间」 — 不是娱乐 App 的活泼感，不是 AI demo 的炫技感，是**像 Linear / Notion 那样让你想用键盘操作的工具感**
- **用户场景**：
  - **白天 PC 桌面端**为主（90% 场景）— 默认明色主题
  - **晚上深夜处理直播录像**也常见（10-30% 场景）— 提供暗色主题切换
  - 用户**专注度高**（不是碎片浏览）— 容忍信息密度大、容忍多层级
  - 用户**急切**（直播刚结束就想发短视频）— 不容忍多余动画延迟

## 3.3 目标市场与语言

- **主市场**：中国大陆（首批用户）
- **主语言**：`zh-CN`（简体中文）
- **多语言切换**：V1 不需要；V2 PH 出海时加 `en`
- **特殊字族要求**：
  - 主用户界面中文：**思源黑体 Noto Sans SC**（数字英文也走同一字族）
  - 等宽字（时间戳 / video_id / 分数）：系统等宽字（SF Mono / Menlo / Consolas）— `font-variant-numeric: tabular-nums`

## 3.4 参考竞品 / 灵感方向

| 参考 | 借鉴什么 | 不借鉴什么 |
|---|---|---|
| **Linear** | 极简克制的工具感、清晰的层级、键盘友好的操作密度、深色主题质感 | 太冷的工业感（video-slicer 是知识类内容，要保留一点"温度"）|
| **Notion** | 暖中性的可阅读性、灰阶克制、不抢内容的色彩用法 | 嵌套折叠的过深层级（video-slicer 是流程性工具，不是知识库）|
| **OpusClip** | SaaS 工具的清晰分步导航、切片卡片的信息密度 | 它的 AI 神秘感渐变（紫粉 hero）— 我们要诚实工具感 |
| **录咖** | 国内用户熟悉的中文排版手感 | 它的活泼配色和 emoji 装饰风 — 太娱乐，跟"知识沉淀"调性冲突 |
| **抖音 / B 站 创作者中心** | 平台规格清单的结构化呈现 | 平台广告气重的视觉、强营销感的 banner |

> **强力建议给 design-spec**：主气质参考 **Linear 工具感 + Notion 可阅读性的混合**；色调比 Linear 暖一点（避免太冷的工业蓝），比 Notion 稳一点（避免太米色像文档软件）。

## 3.5 必备的视觉约束（硬性要求）

- [x] 主题：**明色为主**（白天 PC 场景占 90%）+ **暗色可切换**（深夜处理场景）
- [x] 可访问性：**WCAG AA 对比度**（4.5:1 正文）+ **tabular-nums 数字对齐**（分数 / 时间戳 / 时长必须等宽）
- [x] 必须避免：
  - 紫粉渐变（AI 工具审美疲劳）
  - 大面积彩色 banner（教程平台广告气重）
  - 浮夸动效（loading 闪烁 / 自动 carousel / 弹窗弹跳）
  - emoji 装饰泛滥（保留少量功能性 emoji 如 ⚠️ ✓ ✗ 即可）
- [x] **必须支持的核心感受**：
  - **「快」** — 页面切换、按钮反馈延迟 ≤ 200ms
  - **「准」** — 分数 / 时间戳 / 状态标签视觉上一目了然
  - **「不抢戏」** — 视觉服从内容，让用户看清"金句文本"和"6 维度分数"，UI 不该比内容更扎眼
- [x] **6 维度评分展示的特殊要求**（你产品的核心差异化）：
  - 总分要**显眼**（列表卡片右上大字 + 颜色区分 90+/80-89/70-79）
  - 6 维度细分**展开后**清晰可读（条形图 + 数字 + 维度标签）
  - 类型标签 + 风险等级 用胶囊 chip 设计（不抢主内容戏）

## 3.6 组件清单的视觉密度提示

> 完整组件列表见 [04-pages-components.md](./04-pages-components.md) §4.2-4.5，本表只给"密度倾向"。

| 页面/组件 | 信息密度 | 操作密度 | 视觉重点 |
|---|---|---|---|
| **步骤 1 — 上传视频** | 低（一个 dropzone + 一个 CTA） | 低 | dropzone 的"招呼感" + 文件格式提示清晰 |
| **步骤 2 — AI 分析进度** | 中（3 个并行卡片 + 1 个折叠面板） | 低 | 每个任务进度状态一眼可读（spinner / ✓ / 数字） |
| **步骤 3 — 选切片 + 6 维度评分**（核心交互页） | **高**（N 条卡片 + 总分徽章 + 类型 chip + 6 维度展开 + 勾选）| **高** | **总分徽章 + 6 维度条形图**（核心差异化）；勾选框易点；展开 / 收起平滑 |
| **步骤 4 — 切片结果 + 文案编辑** | 高（N 条卡片 + 抖音/B 站 tab + 双文案文本框 + 预览/下载按钮）| 高 | 双平台文案对比清晰；缩略图 + 视频跳转入口明显 |
| **错误条 / 状态横幅** | 极低 | 低 | 不抢戏但能注意到（顶部 banner 或 toast）|
| **"重新开始" / "返回上一步" 等次级按钮** | 极低 | 低 | 比主 CTA 弱一阶 |

> 注意：步骤 3 和 步骤 4 是**视觉重点页面**。如果时间紧，应该优先保证这两页 UI 精致；步骤 1/2 简洁即可。

## 3.7 design-spec 必须回答的问题（输出契约）

design-spec 在产出 `DESIGN.md` 时必须覆盖以下条目，否则视为 handoff 不完整：

- [ ] 完整明色色板（hex）— 含背景 3 阶 / 文本 3 阶 / 边框 2 阶 / 主强调色 / 状态色（success/warning/danger/info）
- [ ] 完整暗色色板（hex）— 对应明色一一映射
- [ ] **分数着色规则**（关键）— 90+ / 80-89 / 70-79 / 60-74 / <60 五档着色，必须在明暗两套主题都给出
- [ ] **风险等级 chip 配色** — low/medium/high 三档（low 不该太抢眼，high 必须警示但不刺眼）
- [ ] **类型标签 chip 配色** — 金句 4 类 + 知识点 6 类共 10 种类型，统一中性灰即可（避免 10 种颜色花哨）
- [ ] 字体系统 — 含中文 Noto Sans SC 的 `next/font/google` 引入方式 + 字号阶梯（PC 端 ≥14px 正文）
- [ ] 间距与圆角的统一栅格（推荐 4px 或 8px 基础栅格）
- [ ] 动效规范 — 默认 L1 静态优雅；卡片展开/收起 + 主题切换需要平滑过渡
- [ ] 组件基础样式指引 — 按本文件 §3.6 列出的 6 类组件给样式
- [ ] **暗色模式切换器** — UI 位置 + 切换动画 + localStorage 持久化策略
- [ ] **6 维度条形图组件**的可视化方案（这是产品差异化重点，必须给样式细则）
