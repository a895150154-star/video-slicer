## 阶段一：环境搭建 + 转写（2 个坑）

### 坑 #1 — Mac 没装 Homebrew

- **现象**：`brew: command not found`
- **解决**：跑官方安装脚本 + 加到 zsh PATH
- **代码涉及**：无（环境问题）
- **面试 STAR**：[S] 项目启动；[T] 配齐 macOS 开发环境；[A] 用一键脚本装 brew + 手动配 PATH；[R] 体现**从零搭环境能力**

### 坑 #2 — 以为 FFmpeg 能转录

- **现象**：以为 FFmpeg 一站式
- **真相**：FFmpeg 只做音视频处理，转录要 whisper.cpp
- **正确链路**：FFmpeg 提取 16kHz mono WAV → whisper.cpp 转录
- **代码涉及**：`backend/main.py:61-79`
- **面试 STAR**：[S] 选型阶段；[T] 找语音转写方案；[A] 试错后定 whisper.cpp 本地推理（隐私 + 免 token 费）；[R] 体现**工具能力边界判断**

## 阶段二：金句识别 + 违禁词检测（6 个坑）

### 坑 #3 — Anthropic 原生格式 vs OpenAI 兼容格式

- **现象**：调 Claude API 直接 500
- **原因**：蓝衣中转用 OpenAI 兼容（`messages` 数组 + `system` role），不是 Anthropic 原生
- **解决**：把 system prompt 放进 messages 数组的 `role: system`
- **代码涉及**：`backend/main.py:325-368` `call_claude` 函数
- **面试 STAR**：[S] 接 LLM；[T] 调通中转 API；[A] 翻文档 vs 抓包，发现 schema 差异；[R] 体现**理解 API 协议差异**

### 坑 #4 — macOS IPv4 / IPv6 冲突

- **现象**：前端 fetch `localhost:8000` 502 / 500
- **原因**：macOS `localhost` 默认解析到 IPv6 (`::1`)，uvicorn 默认监听 IPv4 (`0.0.0.0`)
- **解决**：后端绑 `127.0.0.1`，前端也用 `127.0.0.1`
- **代码涉及**：`backend/main.py:25` CORS / 前端 `page.tsx` 多处 fetch URL
- **面试 STAR**：[S] 跨端联调；[T] fetch 失败排查；[A] 抓包看 IPv6 ::1 解析 → 改双方都用 IPv4；[R] 体现**底层网络问题 debug 能力**

### 坑 #5 — Claude 返回 JSON 带 markdown fence

- **现象**：`json.loads` 失败 — 输出含 ` ```json...``` ` 包裹
- **解决**：正则剥 ` ```json ` 前缀和 ` ``` ` 后缀再 parse
- **代码涉及**：`backend/main.py:281-323` `clean_json` 第二层
- **面试 STAR**：[S] LLM 输出不稳定；[T] 保证下游 JSON parse 不挂；[A] 加剥 fence 层；[R] 体现**LLM 输出兜底意识**

### 坑 #6 — Claude JSON 字符串值内的中文双引号

- **现象**：JSON 解析失败，特别是 summary 里有 `"开奶茶店"` 这种中文引号引述
- **原因**：模型偶尔用中文 `" "` 作引述，被 JSON parser 误判为字符串结束
- **解决**：写 `_sanitize_json_string` 函数，识别 JSON 字符串值内的裸双引号自动转义
- **代码涉及**：`backend/main.py:229-279`
- **面试 STAR**：[S] LLM 输出极小 bug；[T] 解析 100% 兼容；[A] 写正则 + 字符串状态机识别 vs 字符串外的 `"`；[R] 体现**真实工程极细节**

### 坑 #7 — 并发限流（最有"工程嗅觉"的坑）

- **现象**：金句和知识点 API 同时调用 → **交替失败**（每次都一个成功一个失败）
- **原因**：蓝衣中转对短时间并发做了限流
- **解决**：从并发改串行 + `await asyncio.sleep(3)`
- **代码涉及**：`backend/main.py:682-684` 切片循环；前端 `page.tsx` 步骤 2 sleep
- **面试 STAR**：[S] 调通 LLM 后跑批；[T] "为什么每次都一个成功一个失败"；[A] 从现象（交替）推到本质（限流）→ 串行 + 间隔；[R] 体现**从现象到本质的 debug 能力**

### 坑 #8 — 旧 uvicorn 进程没杀干净

- **现象**：改了代码浏览器仍报旧错
- **原因**：旧 uvicorn 进程没退；新进程启动后旧的还在响应
- **解决**：每次启动前 `pkill -f uvicorn`
- **代码涉及**：约定，不是代码
- **面试 STAR**：[S] 开发期；[T] "明明改了代码为什么没生效"；[A] `lsof -i :8000` 看占用 → kill；[R] 体现**新手最容易栽的坑也能讲清**

## 阶段三：切片 + 文案生成（4 个坑）

### 坑 #9 — FFmpeg 默认不带字幕烧录

- **现象**：要把字幕烧进视频里，但 FFmpeg 版本缺 drawtext / subtitles 滤镜
- **取舍**：**MVP 阶段不死磕**，改为把 SRT 字幕文件和视频一起打包；让博主用剪映加字幕
- **代码涉及**：`backend/main.py:664-670` 仅生成 SRT
- **面试 STAR**：[S] 字幕烧录需求；[T] MVP 实现；[A] 装更全的 FFmpeg vs 砍功能让用户剪映加；[R] 体现 **MVP 取舍能力 — 不是所有功能都要 100% 完美**

### 坑 #10 — Whisper 语义碎片破坏连贯性（最重要的坑）⭐

- **现象**：博主完整一句"那些逻辑思维强的人都在潜移默化用结构化思维"，被 whisper 切成 5-7 个 2 秒碎片
- **后果**：AI 看到 5 个独立片段 → 把每个都标成金句（碎片化）或只挑一段（不完整）
- **解决**：在金句识别 Prompt 里加"先合并连续片段再判断"工作流
- **代码涉及**：`backend/main.py:394-410` GOLDEN_SYSTEM_PROMPT V4 第 1-3 步
- **面试 STAR**：[S] 接 ASR + LLM；[T] AI 切片质量提升；[A] 理解 whisper 按 2 秒停顿切句的特性 → Prompt 工作流强制合并；[R] 体现 **理解 ASR 输出特性 vs LLM 输入要求 的 GAP**
- ⭐ **这是整个项目最有深度的坑**，强烈建议作为面试 Q1（项目最难部分）的标准答案

### 坑 #11 — AI 编造博主原话之外的内容

- **现象**：文案生成时 AI 编出博主原话没有的观点（如"真正厉害的人都在默默践行结构化思维"）
- **后果**：博主发出去会被观众识破，账号信誉损失
- **解决**：在 COPY 文案 Prompt 里加 4 条硬规则
- **代码涉及**：`backend/main.py:572-598` COPY_SYSTEM_PROMPT
- **面试 STAR**：[S] AI 生成阶段；[T] 上线安全意识；[A] 硬规则规约模型 + 互动引导句允许 AI 写；[R] 体现 **产品安全意识 — 不只把功能做出来，还考虑上线后真实风险**

### 坑 #12 — 金句开头丢失核心概念词

- **现象**：金句 text 是"你慢慢就会发现..."，但博主原话开头是"结构化思维这个词，听着好像很简单，但是你慢慢就会发现..."
- **后果**：观众看切片只看到"这个方法"，不知道在讲哪个方法
- **解决**：Prompt 加"指代词必须往前找到指代对象再合并"硬规则
- **代码涉及**：`backend/main.py:406-407` GOLDEN_SYSTEM_PROMPT 原则 1
- **面试 STAR**：[S] V3 prompt 跑通后跟测；[T] 切片质量持续优化；[A] 发现指代词残留 → 加"代词必须往前合并"工作流；[R] 体现 **不断迭代 prompt 的工程能力 — 从"识别金句"到"识别完整可独立理解的金句"**

## Prompt 迭代版本史

> 这块比单点坑更有讲述价值 — 体现你**有完整工程演进**而非一次写完。

### V1：基础版

- **设计**：按观点 / 反差 / 共鸣 / 方法论四类判断
- **问题**：识别出空话（如"这个事情很重要"）

### V2：加入"非金句标准"

- **新增**：排除铺垫类 / 鸡汤类 / 低信息密度类
- **问题**：仍切碎片（whisper 输入特性 + LLM 没合并意识）

### V3：加入"合并连续片段 + 完整性硬规则"

- **新增**：先合并；尾字不能是助词 / 连接词
- **问题**：开头丢核心概念词

### V4：加入"指代词回溯 + 反编造"（当前生产）

- **新增**：指代词必须往前合并到具体概念 + 文案生成的反编造硬规则（C4）
- **状态**：当前生产；运行稳定

> **面试讲述模板**：
> "我做这个项目最大的工程演进是 Prompt 工程。从 V1 到 V4 花了 4 轮迭代，每一轮都是被真实输出 bug 倒逼出来的：
> - V1 → V2：发现空话 → 加非金句负面清单
> - V2 → V3：发现碎片化 → 加'先合并再判断'工作流
> - V3 → V4：发现指代词残留 → 加'前文回溯'硬规则
>
> 这让我学到的不是 Prompt 怎么写，是**每个 Prompt 漏掉的东西都要在真实 case 里才能发现**，而不是 Prompt 写完就 OK。"
