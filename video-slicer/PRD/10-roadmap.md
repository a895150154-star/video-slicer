## 10.5 V3 / 长期方向

V1 跑 30-60 天数据后，根据真实留存可能演化的方向：

1. **守住知识类直播垂直**：深耕 6 类知识点分类 + 6 维度评分 + 推荐发布时间 + 数据回流；锁定为"知识赛道切片工具"
2. **横向扩展到旅游 / 美妆 / 教育**：用户研究里的"创作者分层 onboarding"启用，按类型切换 prompt 和评分维度
3. **MCN 批量场景**：单用户跑顺后做团队协作（多账号 / 审核流 / 分润 / 反佣）
4. **API 输出层**：把识别能力做成 API 卖给已有视频平台（如得到 / 知乎 / 樊登读书）的内部使用

V2.0 决策依据见 §10.5。

## 10.5 已知技术债（MVP 阶段的妥协）

| 技术债 | 来源 | 影响 | 建议解决时机 |
|---|---|---|---|
| 后端硬编码 Claude base URL / model | `main.py:119-120` | 切其他中转商 / 模型要改代码 | V1.5 抽 env |
| 前端硬编码后端 URL | `page.tsx` 多处 `http://127.0.0.1:8000` | 部署上云要改 | V1.5 抽 NEXT_PUBLIC_API_URL |
| 前端 946 行单文件 | `app/page.tsx` | 改任何东西风险高 | V2 物理拆模块 |
| 后端 832 行单文件 | `backend/main.py` | 同上；测试也难 | V2 按业务拆 |
| 无后端单元测试 | — | 回归不可控 | V1.5 加核心函数测试 |
| Claude 输出仅靠 prompt 兜底 schema | `clean_json` | 偶尔会出 schema 漂移 | V2 加 zod 类似的 Python schema 强校验 |
| 频控用 sleep 3s 硬等 | `process-clips` 循环 | 慢；用户等的烦 | V2 改异步队列 + 限流中间件 |
| `videos/` 不清理 | 现状 | 磁盘逐渐塞满 | V1.1 加 TTL |
| 没埋点 / 没分析 | 现状 | 不知道用户卡哪步 | V1.5 接 PostHog 之类 |
| 没用户系统 | 现状 | 切片数据混在一起；公开访问者乱用 | V1.5 加 OTP 登录 |

## 10.5 停损与方向修正决策点

**V1 上线 30 天后**，按以下指标决策：

| 30 天结果 | 决策 |
|---|---|
| **≥ 10 个真实付费用户**（不是面试评审）| **进 V2** — 商业可行性初步验证；按 §10.4 推进 |
| **5-9 个付费用户** | **诊断漏斗瓶颈再定** — 是流量不够？转化率太低？产品本身不行？根据数据决定打哪个补丁 |
| **< 5 个付费用户** | **停损并重新定位**（4 个候选）：（a）旅游博主（基于已有访谈数据，且对工具粘性强）；（b）个人 IP 切片助手（不限直播，长视频通吃）；（c）2C 转 B2B（卖给 MCN 或 已有平台）；（d）转技术博客 / 开源 |

**面试场景的成功定义不同**：
- 完整跑通 4 步流程能 demo 给面试官 → ✅ 已达成
- 12 个真实坑 + V1-V4 prompt 迭代讲清楚 → ✅ [APPENDIX-pitfalls.md](./APPENDIX-pitfalls.md) 已就绪
- 即便商业失败，工程纪律是个人作品集资产
